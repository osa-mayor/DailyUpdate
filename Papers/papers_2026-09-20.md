## 1. [DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression](https://huggingface.co/papers/2609.19969)
**Upvotes**: 91 | **도입 난이도**: 상 | **신뢰도**: 상
**arXiv**: https://arxiv.org/abs/2609.19969

**태그**: LLM, KV-Cache, MoE, Agent, Inference-Optimization, RAG, Multimodal, Optimization

![Thumbnail](images/DeepSeek-V4.1-Flash_Pushing_the_Limits_of_KV_Cache_Compression_img.jpg)

### 📌 한 줄 요약
KV 캐시 압축 기술을 통해 초장거리 컨텍스트와 대규모 에이전트 워크로드를 위한 비용 효율적인 추론 환경을 구축함

### 🔑 핵심 포인트
- CED(Causal Encoder-Decoder) 아키텍처를 통한 프리필/디코딩 연산 효율 최적화
- CSA2(Cross-layer KV cache reuse) 및 FP4 캐싱을 통한 글로벌 KV 캐시 점유율 1/4 수준 절감
- SWA Bounded Replay를 통한 영구 KV 캐시(SSD/Host) 점유율 1/8 수준 절감

### 🧑‍💻 개발자 관점
초장거리 컨텍스트를 다루는 에이전트 개발 시, 하드웨어 자원(HBM/SSD) 제약을 극복하고 추론 비용을 획기적으로 낮출 수 있는 실질적인 가이드를 제공합니다.

### 🚀 실무 적용 아이디어
- 제시된 CED 구조와 MoE 파라미터 활성화 방식의 연산 효율성 벤치마크 수행
- FP4 및 CSA2 기술 적용 시 모델 성능(Perplexity/Accuracy) 저하 여부 검증
- 대규모 컨텍스트 환경에서 SWA Bounded Replay의 데이터 전송 병목 해소 효과 측정

### ⚠️ 리스크/한계
- FP4와 같은 저정밀도 캐싱 적용 시 발생할 수 있는 정밀도 손실 및 모델 성능 저하 리스크
- 특수 아키텍처(CED, CSA2) 사용에 따른 기존 추론 엔진과의 호환성 문제

### 📝 초록 기반 상세 설명
최근 롱 컨텍스트 에이전트의 확산으로 인해 입력 데이터 비중이 커지면서 프리필(prefill) 연산 비용과 KV 캐시 저장 용량 문제가 심각한 병목 현상으로 부상했습니다. 이를 해결하기 위해 552B 파라미터 규모의 멀티모달 MoE 모델인 DeepSeek-V4.1-Flash를 제안합니다. 이 모델은 Causal Encoder-Decoder(CED) 구조를 채택하여 디코딩 시 16B, 프리필 시 8B 파라미터만 활성화하여 연산 효율을 극대화했습니다. 또한 CSA2(Cross-layer KV cache reuse)와 FP4 캐싱을 결합하여 KV 캐시 점유율을 획기적으로 낮추었으며, SWA Bounded Replay 기술로 SSD/호스트 메모리 상의 영구 캐시 크기를 최소화했습니다. 결과적으로 이전 모델 대비 훨씬 작은 캐시 용량으로도 더 뛰어난 성능을 유지하며 대규모 컨텍스트 처리를 가능하게 했습니다.

## 3. [When EOS Tokens Disagree: Understanding Length Inflation in On-Policy Distillation](https://huggingface.co/papers/2609.20511)

**arXiv**: https://arxiv.org/abs/2609.20511

**태그**: LLM, Distillation, Fine-tuning, Inference Optimization, Safety

![Thumbnail](images/When_EOS_Tokens_Disagree_Understanding_Length_Inflation_in_On-Policy_Distillation_img.jpg)

### 📌 한 줄 요약
On-Policy Distillation(OPD) 과정에서 발생하는 모델 간 EOS 토큰 불일치로 인한 답변 길이 팽창 문제를 해결하는 방법론 제시

### 🔑 핵심 포인트
- OPD 과정에서 발생하는 과도한 답변 길이 팽창의 원인을 '종료 토큰 불일치'로 규명
- 단순히 디코딩 중단 세트를 맞추는 것만으로는 충분하지 않음을 증명
- 기능적으로 동일한 EOS 토큰들을 하나의 공유된 의미적 동작으로 처리하여 불일치 완화

### 🧑‍💻 개발자 관점
모델 증류(Distillation) 시 답변이 불필요하게 길어지는 현상을 방지하여 추론 비용을 최적화하고 생성 효율을 높일 수 있습니다.

### 🚀 실무 적용 아이디어
- 학습 시 교사 모델과 학생 모델 간의 EOS 토큰 분포 차이 시각화하기
- 기능적으로 동일한 토큰들을 하나의 로그 확률로 합산하는 방식 적용해보기
- 학습 단계별로 종료 토큰 선호도가 어떻게 변하는지 모니터링하기

### ⚠️ 리스크/한계
- 종료 토큰 불일치가 길이 팽창의 유일한 원인은 아님
- 학습 후반부에 발생하는 특정 길이 팽창 현상은 종료 정렬만으로 해결되지 않을 수 있음

### 📝 초록 기반 상세 설명
On-Policy Distillation(OPD) 과정에서 학생 모델의 답변이 과도하게 길어지며 생성 예산을 소진하는 길이 팽창 현상이 발생합니다. 연구진은 이 현상의 주요 원인이 베이스 학생 모델과 사후 학습된 교사 모델 간의 종료 토큰(EOS) 불일치에 있음을 식별했습니다. 동일한 종료 세트를 사용하더라도 두 모델이 서로 다른 EOS 토큰에 종료 확률을 할당할 수 있으며, 이는 학생의 종료 동작을 억제하는 결과를 초래합니다. 이를 해결하기 위해 기능적으로 동일한 EOS 토큰들을 하나의 공유된 의미적 종료 동작으로 취급하는 방식을 제안했습니다. 실험 결과, 이 방식은 Qwen, Llama, Gemma 등 다양한 모델 제품군에서 길이 팽창 문제를 효과적으로 완화했습니다.
